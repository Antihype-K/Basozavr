Этот проект представляет собой **цифровой двойник (Digital Twin)** системы групповой транспортировки тяжёлого груза на гибких тросовых подвесах.

Система построена на гибридной архитектуре:

* **RSMA** выступает в роли реалистичного физического симулятора (расчёт 6-DOF динамики дронов, упругих связей тросов, коллизий и работы датчиков).
* **Python** выполняет роль верхнеуровневого распределённого «мозга» роя, который принимает телеметрию, рассчитывает траектории, управляет автоматом состояний, гасит колебания груза и отправляет целевые команды уставки дронам по высокоскоростному протоколу **RSMA API (uDTP)**.

## 🏢 1. Общая архитектура и цикл взаимодействия

Симуляция работает по **пошаговому циклу в реальном времени** (шаг интегрирования $\Delta t = 0.01\text{ с}$). На каждом шаге выполняется следующий замкнутый контур:

```text
       ┌────────────────────────────────────────────────────────┐
       │             RSMA Physical Simulator                   │
       │  • Расчет 6-DOF физики дронов, груза и тросов (Гук)     │
       │  • Моделирование аэродинамики, массы и порывов ветра   │
       └──────────────────────────┬─────────────────────────────┘
                                  │
                 Телеметрия       │ (PayloadPose, DronePose_i,
                (UDP / uDTP)      │  CableForce_i)
                                  ▼
       ┌────────────────────────────────────────────────────────┐
       │             Python Control System                      │
       │                                                        │
       │  1. S-образная траектория (Jerk-Limited)               │
       │  2. Flight FSM (LIFT ➔ TRAJECTORY ➔ HOVER ➔ LAND...)   │
       │  3. Anti-Sway Controller (гашение маятника)            │
       │  4. Formation Manager (расчёт N-угольной геометрии)   │
       └──────────────────────────┬─────────────────────────────┘
                                  │
                 Команды          │ (DroneTargetPose_i)
                (UDP / uDTP)      │
                                  ▼
       ┌────────────────────────────────────────────────────────┐
       │             CSV Logger / Visualizer                    │
       │  • Запись пошаговой телеметрии в CSV-файл              │
       │  • Отрисовка 4-панельного дашборда (visualize.py)      │
       └────────────────────────────────────────────────────────┘

```

## 📐 2. Геометрия формации и расчёт уставок (`control/formation.py`)

Чтобы дроны не сталкивались и равномерно распределяли нагрузку при транспортировке, они выстраиваются в правильный $N$-угольник вокруг центра масс груза:

* Координаты $i$-го дрона в горизонтальной плоскости рассчитываются через базовые смещения относительно текущей целевой точки центра груза:

$$dx_i = R \cdot \cos\left(\alpha_i\right)$$

$$dy_i = R \cdot \sin\left(\alpha_i\right)$$

где $R$ — радиус формации (например, $1.414\text{ м}$), а $\alpha_i = \frac{2\pi (i-1)}{N}$ — равномерно распределённые углы для $N$ дронов.

* Высота дронов рассчитывается с учётом длины тросов $L_{cable}$ и радиуса формации $R$, обеспечивая вертикальное преднатяжение:

$$Z_{drone} = Z_{cmd} + \sqrt{\max\left(0.1, L_{cable}^2 - R^2\right)} + \Delta Z_{margin}$$

## 🌊 3. Подавление раскачки груза: Anti-Sway (`control/anti_sway.py`)

Маятниковые колебания груза — главный дестабилизирующий фактор. Если груз отклоняется от вертикали, трос начинает утягивать дрон в сторону, создавая паразитные колебания всей системы.

### Принцип работы Anti-Sway:

1. На каждом шаге алгоритм считывает текущие координаты $i$-го дрона $P_{drone}$ и груза $P_{payload}$, вычисляя вектор отклонения троса и его относительную скорость.
2. Контроллер рассчитывает пропорционально-дифференциальную коррекцию $(\Delta X_{sway}, \Delta Y_{sway})$, заставляя дрон «подбегать» в сторону отклонения маятника:

$$\Delta XY_{correction} = - K_{sway} \cdot (P_{drone}^{xy} - P_{payload}^{xy}) - D_{sway} \cdot V_{rel}^{xy}$$

3. Корректирующий вектор добавляется к целевой точке формации дрона только во время фазы активного полёта по траектории (`TRAJECTORY`), что сглаживает раскачку без создания рывков при взлёте и посадке.

## 🚀 4. Управление полётом и фазы миссии (`control/flight_state_machine.py`)

Процесс транспортировки разбивается на последовательные фазы автомата состояний (**Flight FSM**):

1. **`LIFT` (Плавный подъем)**: Дроны поднимаются по вертикали, плавно выбирая слабину тросов и отрывая груз от земли до целевой высоты (например, $3.0\text{ м}$).
2. **`TRAJECTORY` (Горизонтальный полет)**: Включается генератор $S$-образных траекторий (**Jerk-Limited**) и алгоритм **Anti-Sway**. Рой перемещает груз в финишную точку со сглаживанием ускорения и рывка.
3. **`HOVER` (Стабилизация)**: По достижении финишных координат XY система замирает в режиме висения на короткий таймаут (например, $2.0\text{ с}$), чтобы погасить остаточные колебания перед посадкой.
4. **`LAND` (Посадка груза)**: Целевая высота снижается, аккуратно опуская груз на землю до момента ослабления тросов.
5. **`LAND_DRONES` (Посадка дронов)**: После касания земли грузом дроны плавно снижаются до посадочной высоты ($0.25\text{ м}$).
6. **`FINISHED` (Завершение)**: Миссия успешно выполнена.

## 🔌 5. Взаимодействие через RSMA API и преобразование координат (`utils/rsma_helpers.py`)

Поскольку RSMA использует левостороннюю систему координат (Y — вверх, Z — вперед), а стандартные алгоритмы навигации работают в правосторонней системе координат (Z — вверх), используется модуль конвертации координат:

* **RSMA $\rightarrow$ Python**:

$$\begin{pmatrix} X_{py} \\ Y_{py} \\ Z_{py} \end{pmatrix} = \begin{pmatrix} X_{RSMA} \\ Z_{RSMA} \\ Y_{RSMA} \end{pmatrix}$$


* **Python $\rightarrow$ RSMA**:

$$\begin{pmatrix} X_{RSMA} \\ Y_{RSMA} \\ Z_{RSMA} \end{pmatrix} = \begin{pmatrix} X_{py} \\ Z_{py} \\ Y_{py} \end{pmatrix}$$



Обмен данными осуществляется по топикам протокола RSMA:

* **Подписка**: `PayloadPose`, `DronePose_i`, `CableForce_i`
* **Публикация**: `DroneTargetPose_i`

## 📊 6. Сбор телеметрии и визуализация (`utils/logger.py` & `visualize.py`)

1. **Логирование (`CSVLogger`)**: Каждая итерация цикла сохраняет строку данных в файл `logs/flight_log_YYYYMMDD_HHMMSS.csv` с фиксированием меток времени, текущей фазы, координат груза и всех дронов, а также сил натяжения каждого троса.
2. **Визуализация (`visualize.py`)**: Скрипт анализирует последний записанный файл телеметрии и выводит в едином окне 4 графика:
* **3D Траектория**: Объёмная картина движения груза и всех 6 дронов с точками старта и финиша.
* **Профиль высоты Z**: Динамика изменения высоты всех компонентов по времени/шагам.
* **Натяжение тросов**: Графики сил натяжения для каждого подвеса и средняя нагрузка.
* **Плоскость XY (Вид сверху)**: План горизонтального перемещения группы с сохранением честных пропорций формации ($1:1$).
