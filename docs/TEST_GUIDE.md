# БАСозавр — полный гайд по тестированию

Документ для разработчиков и аналитиков: как по шагам проверить решение, снять характеристики
и оформить результат. Установка ПО описана в [ONBOARDING.md](ONBOARDING.md), найденные проблемы —
в [ANALYTICS.md](ANALYTICS.md).

**Критерии.** ТЗ в репозитории нет, поэтому значения в колонке «Критерий» взяты из эталонного прогона
(видео 25.09, 6 БПЛА / 12 кг). Когда будет ТЗ, замените их требованиями ТЗ.

## T4. Ступенчатый отклик: PID и подъём груза

Главный тест для настройки параметров. Все дроны получают цель «текущая позиция + dy по вертикали».
Скрипт пишет отклик и считает показатели.

**Шаги**
1. Перезапустить Play Mode, чтобы рой стоял в исходном положении.
2. Запустить:
   ```bash
   python step_test.py --drones 6 --dy 5 --hold 20 --csv results/t4_dy5.csv
   python step_test.py --drones 6 --dy 12 --hold 30 --csv results/t4_dy12.csv --land
   ```
3. Наблюдать в Unity: тросы натягиваются, груз отрывается от земли.

**Что выводит скрипт**

| Колонка | Смысл |
|---|---|
| нараст., с | время от 10 до 90 % высоты ступени |
| перерег., % | насколько дрон проскочил целевую высоту |
| устан., с | момент, после которого дрон не выходит из коридора ±5 % ступени |
| ошибка, м | установившаяся ошибка по высоте (последние 10 % записи) |
| F ср / F max | натяжение троса на удержании (вторая половина записи) |
| Суммарное натяжение | сумма средних натяжений по всем тросам |

**Критерии (эталон — заменить на ТЗ)**

| Показатель | Критерий |
|---|---|
| Перерегулирование | ≤ 20 % |
| Время установления (dy = 12 м) | ≤ 10 с |
| Установившаяся ошибка | ≤ 0,3 м |
| Разброс натяжений между тросами | (max − min) / среднее ≤ 45 % (эталон: 21–33 Н) |
| Суммарное натяжение / вес груза | ≈ 1,2–1,4 (эталон: 162 / 117,7 = 1,38). Меньше 1 — груз не висит полностью на тросах |
| Груз оторвался от земли | да |

**Как настраивать.** Поля `positionKp/Ki/Kd` в префабе `Gyrocopt`. После каждого изменения
перезапустите Play Mode и повторите T4, все прогоны записывайте в протокол.

| Наблюдение | Что крутить |
|---|---|
| Большое перерегулирование, колебания | уменьшить `Kp` или `Ki`, увеличить `Kd` |
| Медленно набирает высоту | увеличить `Kp` |
| Висит ниже цели (ошибка не уходит) | увеличить `Ki` |
| Медленно дрейфует и раскачивается после удержания | интегратор накопил ошибку (проблема №5): уменьшить `Ki` |
| Проседает при боковом движении | упирается в `maxForce` (проблема №6) |

> Внутри Unity параметры троса (`stiffness`, `damping`, `maxForce`) пока можно менять только
> в коде `RSMASwarmEnvironment.cs` (проблема №10).

## T5. Полная миссия доставки

Требует Python-кода управления роем. Сценарий эталона: взлёт с площадки (синий круг) → перенос груза →
выгрузка в оранжевом круге → отцепка тросов → возврат → посадка.

**Шаги**
1. Unity → Play.
2. Параллельно с записью телеметрии:
   ```bash
   python swarm_check.py --drones 6 --duration 100 --rate 10 --csv results/t5_run1.csv
   ```
3. Запустить Python-управление роем.
4. Делать скриншоты HUD на каждом этапе. После полёта запустить файл визуализации из Python-кода
   и сохранить графики.

**Чек-лист по этапам**

| Этап (HUD) | Проверка | Критерий (эталон) | ✓ |
|---|---|---|---|
| Взлёт | все дроны поднялись синхронно, груз оторвался | без рывков, без касаний дронов | |
| Перенос груза | высота груза | 12,2 ± 0,5 м | |
| | скорость груза | ≤ 4,6 м/с | |
| | натяжение тросов (сумма, мин/макс) | ≈ 160 Н, 21–33 Н | |
| | раскачка груза | ≤ 4° | |
| Выгрузка | груз опущен в оранжевый круг | «До точки» ≤ 0,3 м | |
| | раскачка в момент касания | ≤ 0,5° | |
| | тросы ослаблены перед отцепкой | натяжение < веса груза (сейчас 188 Н — не проходит, проблема №13) | |
| Отцепка | «тросы отцеплены», груз остался на земле | груз не сдвинулся | |
| Возврат на базу | рой летит к площадке | без столкновений | |
| Посадка | все дроны на площадке | «До точки» ≤ 0,2 м | |
| Итог | «Рейсов» увеличился на 1 | **сейчас остаётся 0** (проблема №14) | |
| Итог | время / путь | ≈ 79 с / 168 м | |

## T7. Грузоподъёмность (поиск предела)

Цель — найти реальный запас по грузоподъёмности (задача 2 из плана команды).

1. Оставить один рой (6 дронов). В `RSMASwarmEnvironment` менять `payloadMass`:
   **12 → 15 → 20 → 30 → 40 → 60 → 80 → 100** кг.
2. Для каждой массы выполнить T4 (`--dy 12 --hold 30`). Если есть Python-управление, ещё и T5.
3. Записать:

| Масса, кг | Груз оторвался | Ошибка высоты, м | Перерег., % | F max троса, Н | Суммарное F, Н | Раскачка, ° (T5) | Итог |
|---|---|---|---|---|---|---|---|
| 12 | | | | | | | |
| 15 | | | | | | | |
| … | | | | | | | |

**Признаки отказа (предел достигнут)**
- груз не отрывается или дроны проседают > 1 м ниже цели;
- `F max` троса упирается в 250 Н: сработало ограничение троса;
- ошибка высоты > 0,5 м или колебания не затухают.

**Ориентир:** по расчёту из ANALYTICS.md теоретический предел около 100 кг. Запас = предел / 12 кг.

> Тяга 250 Н на дрон массой 2,5 кг завышена относительно реальных БПЛА. Если ТЗ задаёт тяговооружённость,
> сначала выставьте реальный `maxForce`, потом ищите предел.

## T8. Конфигурации роя

Для каждой строки повторить T4 (и T5, если есть Python-управление):

| Конфигурация | numDrones | payloadMass | radius | cableLength | Цель проверки |
|---|---|---|---|---|---|
| A (базовая) | 6 | 12 | 3 | 5 | эталон |
| B | 5 | 10 | 3 | 5 | меньше дронов |
| C | 4 | 8 | 3 | 5 | минимальный рой |
| D | 6 | 12 | 2 | 5 | узкий строй: тросы ближе к вертикали, натяжение должно упасть |
| E | 6 | 12 | 3 | 7 | длинный трос: меньше угол, но больше раскачка |
| F | 4 | 12 | 3 | 5 | перегрузка малого роя |

тратится впустую. Эти цифры пойдут в презентацию как обоснование выбора параметров.
