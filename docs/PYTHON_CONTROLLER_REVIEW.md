# Разбор Python-контроллера (gitlab.grimdark.ru/development/rsma-swarm-delivery-system)

Репозиторий: 8 коммитов, ветка `main`, автор kms0207, 36 файлов. Это Python-«мозг» роя для RSMA: подключается к серверу Unity по ZeroMQ
(`RSMAClient`, REQ → RouterSocket на порту 5555 — тот же `NetMqServer`, что в этом репозитории), читает `PayloadPose`, `DronePose_i`,
`CableForce_i`, публикует `DroneTargetPose_i`.

## Как устроено

| Модуль | Что делает |
|---|---|
| `Source/main.py` → `control/swarm_controller.py` | цикл управления: телеметрия, автомат, цели дронам, CSV-лог |
| `control/flight_state_machine.py` | фазы `LIFT` → `TRAJECTORY` → `HOVER` (2 с) → `LAND` → `LAND_DRONES` → `FINISHED` |
| `control/trajectory.py` | `JerkLimitedTrajectory` (ограничение ускорения и рывка по осям) |
| `control/formation.py` | N-угольник вокруг груза, радиус 1,414 м |
| `control/anti_sway.py` | поправка к цели каждого дрона по углу троса |
| `utils/rsma_helpers.py` | Unity (Y вверх) ↔ Python (Z вверх) |
| `utils/logger.py`, `visualize.py` | CSV-лог каждого шага и 4-панельный график (3D, высота, натяжения, план) |
| `RSMA/` | клиент и сериализация топиков (`Pose`, `Float32`) |

Топики совпадают с тем, что публикует Unity-сторона этого репозитория: `PayloadPose` (добавлен в `RSMASwarmEnvironment`),
`DronePose_i` (`Quadrocopter`), `CableForce_i` (`RSMACable`), `DroneTargetPose_i` читает `Quadrocopter`. Формат `Pose` и ответы
`{"status", "data"}` совместимы с их клиентом. Логика миссии у них — в Python (этапы, раскачка), у сцены 1 в этом репозитории —
встроенная C#-миссия (`SwarmScriptedFlight`); одновременно их запускать нельзя (обе задают цели дронам).

## Что нашлось (проверено на модели, `Tools/SwarmModel/python_controller_check.py`)

Конфигурация: 6 БПЛА, 12 кг, трос 2 м, R 1,414 м, `v_max` 0,8, ПИД префаба `Quadrocopter` 5/1/1,5.

1. **`anti_sway.py` сжимает строй, а не гасит раскачку.** Угол троса считается по вектору «дрон − груз», который уже содержит радиус
   строя: для каждого дрона получается ≈ 0,72 рад (≈ 41°) без всякой раскачки. Поправка `−K·угол` = −1,08 м тянет каждый дрон к центру
   (проверено на их коде: на номинальной геометрии поправка −1,08 м на каждом шаге). Средний угол тросов в полёте падает с 34° до
   22°, натяжение с 142 до 127 Н, дроны сближаются.
   Дополнительно на первом вызове `prev_angle_vector = 0`, и производная `(угол − 0)/dt` даёт разовый выброс уставки порядка десятков метров.
2. **Заводской ПИД 5/1/1,5 слишком мягкий для груза** (то же написано в комментарии `SwarmDeliveryScene` про Kp = 5). Для их скорости
   0,8 м/с лучше 10/2/12; для быстрой C#-миссии сцены 1 лучше 40/12/14 (на 10/2/12 там пик 5,5° против 2,3°).
3. **`JerkLimitedTrajectory` почти не отличается от простой трапеции** при их параметрах (пик 5,1° против 4,4°); перелёт груза
   около 1 м есть у любого профиля, его даёт мягкий ПИД, а не траектория.

| Вариант (без ветра) | Пик раскачки с момента старта | Пик в полёте | Угол тросов |
|---|---|---|---|
| сейчас: ПИД 5/1/1,5 + anti-sway как в репозитории | 4,76° | 3,62° | 22° |
| исправлен anti-sway | 4,37° | 3,01° | 38° |
| ПИД 10/2/12 | 3,68° | 2,85° | 23° |
| **ПИД 10/2/12 + исправленный anti-sway** | **2,83°** | **2,00°** | **42°** |

В ветре 10 ± 3 м/с: пик 10,2° → 6,0°, точность в точке 0,55 → 0,17 м.

## Что сделать

1. Применить патч к их репозиторию: `Tools/SwarmControl/gitlab-patches/anti_sway_fix.patch`
   (`git apply` из корня их репозитория). Он передаёт в `compute_sway_correction` номинальное смещение дрона (`self.offsets[d_id]`)
   и убирает выброс на первом шаге. Менять K и D не нужно.
2. Для Python-миссии поставить ПИД префаба `Assets/Prefabs/Drones/Quadrocopter.prefab` 10 / 2 / 12 (`positionKp/Ki/Kd`).
   C#-миссия сцены 1 переопределяет ПИД на 40/12/14 в `SwarmDeliveryScene`, поэтому ей это не мешает.
3. Мелочи в их README: после `git clone` указан `cd RSMASwarmDelivery` (папка называется `rsma-swarm-delivery-system`), упомянуты
   подмодули, которых нет (`.gitmodules` отсутствует), связь названа UDP, хотя это TCP/ZeroMQ, `python main.py` надо запускать из `Source/`,
   `requirements.txt` в UTF-16.

Проверка в Unity: запустить их `main.py` на сцене без встроенной миссии (на объекте `SwarmDelivery` отключить `SwarmDeliveryScene`,
у `RSMASwarmEnvironment` включить `buildOnStart`) и сравнить пик раскачки в `visualize.py` с таблицей.
